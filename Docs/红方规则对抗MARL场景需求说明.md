# 红方规则对抗 MARL 场景需求说明

版本：V2.0
适用工程：UE5.3 Lyra TacticalMARL
目标地图：`/Game/MARL/UrbanDepot/Maps/L_MARL_UrbanDepot`

## 1 项目目标

本次升级在现有侦察打击闭环上增加红方规则战术，使红方发射车、狙击手和步枪兵能够基于局部感知主动攻击蓝方 UAV 与 UGV。蓝方继续通过 TacticalMARL 的 JSON UDP 接口接收观测、输出高层动作，并最终以 MARL 策略完成侦察、规避、压制、持续跟踪、合法打击和任务重组。

升级后的研究对象是一个非对称对抗环境：红方使用固定且可配置的规则策略，蓝方使用 scripted baseline 和后续训练得到的 MARL 策略。第一阶段不训练红方，也不允许红方直接读取蓝方全局真实状态。

## 2 当前基线

现有场景包含 3 架蓝方 UAV、3 辆蓝方 UGV、3 名红方步枪兵、1 名红方狙击手和 1 辆红方反无人机发射车。现有系统已实现蓝方高层任务控制、UAV 与 UGV 运动、红方 GAS 生命值、目标确认与跟踪、合法打击、Episode Reset、JSONL 轨迹和 UDP 并行 Agent 接口。

本次升级必须保留现有接口和 scripted recon strike 流程。新增功能不得通过修改任务状态或直接写入目标生命绕过 TacticalMARL 动作、感知和伤害链。

## 3 作战场景

红方在 UrbanDepot 红方区域内保护反无人机发射车。步枪兵承担外围警戒与近程防御，狙击手承担远程观察和对地面目标的精确射击，发射车承担对 UAV 的探测、锁定和防空攻击。蓝方从基地出发，通过 UAV 和 UGV 协同搜索目标区，识别威胁，保持发射车跟踪并在红方火力下完成反击。

标准任务流程为：

```text
Episode Reset
→ 红方进入固定防御部署
→ 蓝方搜索 CandidateArea
→ 红方局部发现蓝方并共享告警
→ 蓝方确认发射车和防御节点
→ 红方锁定或攻击蓝方
→ 蓝方规避、压制、重新分配角色
→ 蓝方保持目标 Track
→ 合法打击发射车
→ 毁伤评估
→ Success Failure 或 Truncated
```

## 4 阵营与单位

| 阵营 | 单位 | 数量 | 主要能力 | 任务价值 |
|---|---|---:|---|---|
| 蓝方 | Tactical UAV | 3 | 搜索、确认、持续跟踪、规避、打击 | 侦察与空中打击核心 |
| 蓝方 | Tactical UGV | 3 | 地面接近、掩护、压制、监视 | 地面支援与火力吸引 |
| 红方 | Rifleman | 3 | 巡逻、掩体、近程警戒、交叉火力 | 外围防御节点 |
| 红方 | Sniper | 1 | 远程观察、精确射击、换位 | 对 UGV 的高威胁节点 |
| 红方 | Anti UAV Launcher | 1 | 搜索、确认、锁定、发射、冷却 | 主要任务目标与防空核心 |

## 5 红方规则战术

### 5.1 共同感知约束

红方只能依据距离、视场角、视线遮挡、最后发现位置和共享告警进行决策。建筑物必须能够遮挡探测和射击。红方不得读取蓝方全局坐标、当前 MARL 动作或未被感知的角色状态。

红方共享告警状态为：

```text
Unaware → Suspicious → Alerted → Tracking → Engaging → LostContact → Unaware
```

共享信息只包含目标类型、最后发现位置、发现时间、置信度和来源单位，并具有传播延迟和置信度衰减。

### 5.2 发射车战术

发射车按扇区扫描 UAV，经过持续确认后进入锁定。锁定完成前必须向蓝方提供可观察预警。发射后进入冷却，弹药或热量受限。命中概率受距离、目标速度、飞行高度、遮挡和规避动作影响。

默认优先级为 StrikeRole UAV、维持跟踪的 UAV、WideReconRole UAV、其他 UAV。第一版不攻击 UGV。

### 5.3 狙击手战术

狙击手在预设观察点警戒，优先攻击停止、低速或长时间暴露的 UGV。受到压制或连续暴露后在有限掩体点之间换位。狙击手不得攻击被完全遮挡的目标。

### 5.4 步枪兵战术

步枪兵围绕发射车构成近程防御，执行巡逻、警戒、进入掩体、交叉火力和有限追击。主要攻击进入防御区的 UGV；只有 UAV 进入低空近距范围时才允许射击 UAV。

## 6 蓝方 MARL 任务

蓝方必须学会在部分可观测条件下完成以下能力：

- 分配 WideReconRole、CloseReconRole、GroundSupportRole 和 StrikeRole。
- 搜索和确认发射车及其防御节点。
- 维持目标 Track，跟踪丢失后重新捕获。
- 对锁定、来袭和受击信号进行规避。
- 使用 UGV 压制或牵制步兵和狙击手。
- 在 Agent 失能后重新分配侦察、跟踪和打击角色。
- 满足确认、跟踪和授权条件后打击发射车。
- 在时间、损失和通信成本约束下完成任务。

## 7 动作空间

第一版继续使用高层动作，不要求 MARL 学习底层飞行动力学或车辆驾驶：

```text
Action = Role + Task + Target or Zone + Waypoint + Optional Parameters
```

必须支持的任务包括 `search`、`confirm`、`track`、`reacquire`、`approach`、`evade`、`take_cover`、`suppress`、`engage`、`support` 和 `rtb`。UE 负责路径、转向、碰撞、避障、瞄准、射击和视觉表现。

## 8 Observation V2

每个蓝方 Agent 的个体观测至少包含：

- Self：位置、速度、航向、生命值、存活状态、当前角色和任务。
- Threat：是否被发现、是否被锁定、来袭方向、预计命中时间、最近受击方向。
- Target：可见性、相对位置、检测置信度、Track Quality 和目标类型。
- Neighbor：队友相对位置、生命值、角色、任务和通信质量。
- Mission：当前阶段、目标区域、授权状态、剩余时间和己方损失。
- Local Map：附近掩体、障碍和危险方向的结构化表示。
- Action Mask：当前状态下合法的高层动作。

全局状态可以向 centralized critic 提供更完整的信息，但 decentralized actor 不得获得未感知的红方精确位置和内部冷却状态。

## 9 蓝方生命与受击

UAV 和 UGV 必须具有可复位的生命值、受击、失能和死亡状态。红方攻击必须通过统一伤害接口改变该状态。失能 Agent 停止执行动作并在 Observation 中标记，不立即从世界中无痕消失。

UE 中必须显示命中闪烁、弹道或来袭特效、爆炸、生命变化以及明显的失能状态。UAV 可采用坠落或受控落地表现，UGV 可采用停车、冒烟或禁用效果。

## 10 Reward 与终止条件

团队奖励继续覆盖区域搜索、首次发现、目标确认、Track 建立与保持、合法打击、目标毁伤和 Mission Success。新增奖励与惩罚包括：

- 成功规避来袭攻击。
- 压制或摧毁关键防御节点。
- 保持关键侦察 Agent 存活。
- Agent 损失后的有效角色重组。
- UAV 或 UGV 受伤与损失惩罚。
- 长时间暴露在红方射界惩罚。
- 无效压制、非法打击、超时和越界惩罚。

蓝方在发射车被中和且任务链合法完成时胜利。红方在蓝方关键任务能力全部失效、蓝方超过时间或步数限制，或发射车存活至防御时限结束时胜利。

## 11 Episode Reset 与可复现性

Reset 必须恢复所有蓝红单位的位置、生命、存活、任务、弹药、冷却、告警状态、Track、烟雾与临时特效，并清理弹丸和延迟事件。相同 seed 下红方战术选择、命中随机数和蓝方 scripted baseline 必须可重复。

规则结构保持固定，但警戒方向、反应延迟、命中误差、掩体选择和冷却时间允许在 seed 控制下随机化，以避免蓝方只记忆固定时间表。

## 12 难度课程

| 级别 | 红方能力 | 蓝方训练重点 |
|---|---|---|
| D0 | 红方不攻击 | 保持现有侦察打击基线 |
| D1 | 探测与可见告警 | 学习威胁识别 |
| D2 | 发射车攻击 UAV | 学习空中规避与角色接替 |
| D3 | 狙击手攻击 UGV | 学习地面掩护和压制 |
| D4 | 步兵协同与共享告警 | 学习多威胁协同 |
| D5 | 发射车转移、烟雾和通信限制 | 学习完整对抗策略 |

## 13 可见场景要求

每项核心功能必须在 UE 游戏场景中可观察，不得仅通过日志宣称完成。场景至少应显示单位阵营、生命值、红方告警阶段、探测或锁定线、来袭提示、弹道、命中效果、失能状态、Mission Phase 和 Episode 结果。

每个阶段验收应保留启动命令、固定 seed、关键日志和至少一份截图或短视频说明。可见效果只用于解释战术状态，不得泄露给 MARL actor 未授权的全局信息。

## 14 非功能要求

- 保持 UE 5.3 与 MSVC 14.38 编译兼容。
- 红方规则 AI 在相同 seed 下可复现。
- 6 个蓝方 Agent 的 JSON UDP 接口保持向后兼容。
- 单 Episode 不出现重复 Agent ID、重复 Controller 或未复位单位。
- 所有新增日志继续写入 `Saved/TacticalMARL`，不提交大体积运行数据。
- scripted baseline 必须先通过，再开始 MARL 训练。
- D0 到 D4 每级至少通过短测与批量 Episode 验收。

## 15 第一阶段完成定义

第一阶段完成时，玩家能够在 UE 中看到发射车扫描、确认、锁定和攻击 UAV，UAV 显示预警、规避、受击及失能，Episode 能正确判定双方胜负并 Reset。Python 可读取新增 Observation、输出规避和反击动作，并生成包含攻防事件的 JSONL 轨迹。该闭环稳定后，再加入狙击手、步枪兵协同和正式 MARL 训练。
