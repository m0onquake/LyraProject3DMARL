# 红方规则对抗开发与验收计划

版本：V2.0
实施分支：`feature/red-defense-marl-upgrade`
适用工程：UE5.3 Lyra TacticalMARL

## 1 开发目标

本计划把现有单向侦察打击场景升级为可训练的规则红方对抗环境。红方使用局部感知和固定战术，蓝方继续通过 JSON UDP MARL 接口进行高层协同决策。所有步骤均采用“代码完成、实际 UE 场景可见、自动化检查通过、Episode 可复位”四项验收门槛。

任何阶段不能只凭编译成功或日志字段存在判定完成。除纯文档阶段外，每一步都必须提供可直接启动的 UE 游戏场景，并用固定 seed 演示该阶段新增行为。

## 2 总体技术路线

```text
蓝方可受击状态
→ 红方感知与共享告警
→ 发射车防空攻击
→ 狙击手对地攻击
→ 步枪兵近程协同
→ 蓝方 scripted 反制基线
→ MARL Observation V2 与奖励
→ 严格 Step Reset 与压力测试
→ 课程训练与 MAPPO
→ 多地图和泛化评估
```

红方战术在 UE 内运行，不通过 Python 操作。蓝方高层动作仍通过现有 UDP 接口发送。UE 负责感知、移动、瞄准、弹道、伤害、视觉效果和底层控制。

## 3 统一验收规则

每个阶段必须同时满足：

1. 使用 MSVC 14.38 成功编译 `LyraEditor`。
2. 在 `L_MARL_UrbanDepot` 中启动实际 Game 或 PIE 场景。
3. 新行为在场景中可见，并有 HUD、标记、弹道、动画或特效支撑。
4. 使用固定 seed 完成至少一个可重复的演示 Episode。
5. Episode Reset 后位置、生命、任务、告警、弹药、冷却和临时对象恢复正确。
6. JSONL 记录新增状态和事件，且可逐行解析。
7. 日志无 Fatal、重复 Agent、重复 Controller、红方未复位和 UDP 协议错误。
8. 保存启动命令、结果摘要和截图或短视频说明。

## 4 S0 基线固化与可视化入口

### 开发内容

- 固化当前 3 UAV、3 UGV、3 Rifleman、1 Sniper 和 1 Anti UAV Launcher 的初始部署。
- 增加调试 HUD，显示 Episode、seed、Mission Phase、红方告警阶段和双方存活数。
- 增加可开关的 Agent ID、Role、Task 和生命值标签。
- 固化 D0 被动红方作为回归基线。

### UE 可见场景验收

启动地图后能够明确看到蓝方基地、红方防御区、全部单位和主要目标标记。HUD 显示 `Difficulty D0`、固定 seed 和 Mission Phase；单位头顶标签与 JSON Agent ID 一致。

### 自动化验收

- 运行现有 seed 42 scripted Episode，结果仍为 `mission_success`。
- Agent 数量为 6，红方单位数量为 5。
- 基线 Observation、Reward 和 JSONL schema 不发生非预期变化。

### 通过标准

基线演示和回归测试通过后才能开始伤害系统改造。

## 5 S1 蓝方生命 受击与失能

### 开发内容

- 为 UAV 和 UGV 增加统一的可复位 Health Component。
- 实现伤害、受击来源、死亡或失能、无效动作掩码和 Observation 字段。
- 实现 UAV 坠落或受控落地状态、UGV 停车与冒烟状态。
- 保证失能 Agent 不再接受正常动作，但保留实体供观察和日志记录。

### UE 可见场景验收

在专用演示模式中使用固定测试伤害命中一架 UAV 和一辆 UGV。场景中必须看到生命值下降、命中闪烁或爆炸、UAV 失能表现和 UGV 停车冒烟。HUD 的存活数量同步变化。

### 自动化验收

- 伤害前后 Health 数值和 `alive disabled` 状态正确。
- 失能 Agent 的 Action Mask 禁止普通任务。
- Reset 后全部蓝方单位恢复满生命、原位置和 Idle 状态。
- 连续执行 10 次 Reset 不出现重复 Pawn 或 Controller。

### 通过标准

UAV 和 UGV 均能够受击、失能、记录和复位，且不破坏原 scripted policy。

## 6 S2 红方局部感知与共享告警

### 开发内容

- 新增红方 Threat Sensor，支持距离、FOV、LOS 和检测置信度。
- 新增共享告警状态和最后发现位置，包含传播延迟与置信度衰减。
- 红方不得读取未被感知的蓝方全局位置。
- 所有状态由 seed 控制并在 Reset 时清除。

### UE 可见场景验收

启用调试显示后，可以看到红方传感器扇区、被建筑遮挡的探测失败、告警状态颜色变化和最后发现位置标记。蓝方 UAV 进入视场时红方从 Unaware 依次进入 Alerted 或 Tracking，离开 LOS 后进入 LostContact。

### 自动化验收

- 遮挡状态下不产生有效检测。
- 告警传播延迟和置信度衰减符合配置。
- 相同 seed 与轨迹产生相同告警序列。
- Reset 后所有红方恢复 Unaware，最后发现位置为空。

### 通过标准

红方能够依赖局部感知形成可复现告警，且不存在全局真值泄露。

## 7 S3 发射车防空攻击

### 开发内容

- 实现扫描、确认、锁定、预警、发射、冷却和重新搜索状态机。
- 加入距离、高度、速度、遮挡和规避对命中概率的影响。
- 实现弹药或热量限制和优先目标选择。
- 第一版只攻击 UAV，并优先攻击 StrikeRole 和 Track 维持者。

### UE 可见场景验收

场景中发射车能够转向或显示扫描状态，锁定 UAV 时出现明确预警线和倒计时，随后显示弹道、导弹或光束、爆炸与 UAV 受击效果。UAV 躲入建筑遮挡后锁定应中断或命中概率明显下降。

### 自动化验收

- 未确认或无 LOS 时不能发射。
- 发射间隔、弹药和冷却符合配置。
- 命中通过统一蓝方伤害接口生效。
- D2 固定 seed 下至少完成命中、规避、失锁和 Reset 四类测试。

### 通过标准

发射车能够对 UAV 形成真实训练压力，且每次攻击具有可观察预警和可解释原因。

## 8 S4 狙击手对地攻击

### 开发内容

- 实现观察、瞄准、射击、冷却、失去目标和换掩体行为。
- 优先选择低速、静止或长时间暴露的 UGV。
- 受到压制后在有限候选掩体间移动，不进行全图追击。

### UE 可见场景验收

场景中能够看到狙击手在观察点瞄准 UGV、显示短暂瞄准提示、发射可见弹道并造成 UGV 受击。UGV 躲到建筑后射击停止；狙击手受到压制后移动到另一个预设点。

### 自动化验收

- 无 LOS 时不造成伤害。
- 静止 UGV 的目标优先级高于快速移动 UGV。
- 换位位置限定在红方防御区。
- Reset 后恢复初始观察点、弹药和冷却。

### 通过标准

狙击手为 UGV 路径和停留时间提供可学习的风险，而不会跨地图作弊射击。

## 9 S5 步枪兵近程协同

### 开发内容

- 实现巡逻、进入掩体、区域警戒、交叉火力、短距离追击和撤回。
- 三名步枪兵根据 Agent ID 分配不同防御扇区和射界。
- 只在低空近距条件下攻击 UAV，主要攻击进入防御区的 UGV。

### UE 可见场景验收

蓝方 UGV 接近红方区域时，三名步枪兵分别进入不同掩体并形成交叉火力。UGV 撤出防御区后，步枪兵停止无限追击并回到岗位。场景中能够看到移动、瞄准、枪口火焰、弹道和命中效果。

### 自动化验收

- 三名步枪兵的目标和掩体分配不重复拥堵。
- 追击范围不超过配置边界。
- 完全遮挡时不持续造成伤害。
- 连续 10 个 Episode 后红方位置和状态均正确复位。

### 通过标准

红方近程防御能够形成空间约束，但不会通过无限追击或全局感知破坏任务公平性。

## 10 S6 蓝方 scripted 反制基线

### 开发内容

- 扩展 scripted policy，增加规避、掩体接近、压制、支援和角色接替。
- 发生 UAV 损失时自动重新指定 Track 和 Strike Agent。
- UGV 根据防御节点和危险区选择不同编队目标。

### UE 可见场景验收

运行固定 seed 后，可以看到 UAV 收到锁定预警并规避，一架 UAV 失能后另一架接替跟踪或打击；UGV 利用建筑接近并压制红方。场景最终显示蓝方成功或有明确失败原因，而不是单位静止等待超时。

### 自动化验收

- D0 保持原基线成功率。
- D1 至 D3 各运行至少 10 个 Episode，并输出成功率、损失率和终止原因。
- 不允许 scripted policy 读取个体 Observation 未提供的红方真值。
- JSONL 完整记录威胁、规避、压制、受击和角色接替事件。

### 通过标准

正式 MARL 训练前必须存在能够闭环完成对抗任务的 scripted baseline。

## 11 S7 MARL 接口 V2

### 开发内容

- 增加 Health、Threat、Neighbor、Mission、Local Map 和 Action Mask。
- 增加 evade、take_cover、suppress 和 support 高层动作。
- 增加团队奖励、个体伤害归因、Agent 损失和角色重组奖励。
- 为 centralized critic 输出 Global State，为 actor 保持部分可观测输入。

### UE 可见场景验收

在调试 HUD 中选择任一蓝方 Agent 时，显示该 Agent 实际可见的威胁、Track、邻机、动作掩码和当前高层任务。切换不同 Agent 时信息范围应不同，不能全部显示相同全局真值。

### 自动化验收

- JSON schema 版本升级并保留兼容说明。
- 所有 Agent 每步返回固定形状或明确的变长字段约定。
- 非法动作被 Action Mask 阻止并记录原因。
- Reward 分项总和与每 Agent 总奖励一致。

### 通过标准

Python 能稳定执行 `reset step state`，并可直接接入训练框架而无需解析 UE 私有对象。

## 12 S8 严格 Step Reset 日志与压力测试

### 开发内容

- 将真实时间 sleep 驱动逐步替换为可控的仿真步进协议。
- Reset 清理弹丸、烟雾、定时器、告警、冷却、伤害和失能状态。
- 扩展 JSONL 和压力测试报告，加入红方攻击与蓝方损失指标。

### UE 可见场景验收

提供慢速可视演示模式和高速无渲染测试模式。慢速模式中每次 step 可通过 HUD 观察状态变化；Reset 时所有单位同时回到部署点，场景中不残留弹丸、烟雾或上一 Episode 的失能对象。

### 自动化验收

- 先执行 10 Episode 冒烟测试，再执行 100 Episode 稳定性测试。
- 检查 UDP 错误、Reset 失败、重复 Agent、红方未复位、弹丸残留和持续内存增长。
- D0 至 D4 均生成 JSON 和 Markdown 报告。
- 完整 1000 Episode 作为发布前验收，耗时过长时必须保留可继续执行的命令和中间结果。

### 通过标准

100 Episode 无协议或 Reset 错误，内存无持续增长；发布前完成或明确续跑完整 1000 Episode。

## 13 S9 课程训练与 MAPPO

### 开发内容

- 按 D0 至 D5 逐级训练，先单威胁再组合威胁。
- 建立 MAPPO baseline、checkpoint、评估脚本和 TensorBoard 指标。
- 固定训练 seed 范围并使用独立评估 seed。

### UE 可见场景验收

加载训练 checkpoint 后，在 UE 场景中可见蓝方根据红方告警、锁定和受击动态改变路线与角色。至少提供成功、失败和 Agent 损失后恢复三种可重复回放。

### 自动化验收

- 与 random policy 和 scripted policy 比较成功率、回报、损失率、步数和耗时。
- 训练曲线、评估结果和 checkpoint 元数据完整。
- 评估不使用训练 Episode seed。

### 通过标准

MAPPO 在至少一个主动防御难度上显著优于 random policy，并在独立 seed 上达到预先设定的最低成功率。

## 14 S10 多地图与泛化

### 开发内容

- 将硬编码搜索点和红方部署改为 MissionZone、SpawnPoint 和 CoverPoint 数据驱动配置。
- 增加至少一张不同建筑和道路布局的评估地图。
- 支持目标、掩体、警戒方向和通信条件随机化。

### UE 可见场景验收

使用同一策略分别启动 UrbanDepot 和第二张地图。两张地图均能看到完整红方部署、局部感知、攻击、蓝方反制和任务结束，不依赖地图特定的硬编码坐标。

### 自动化验收

- 训练地图和未见评估地图分别输出指标。
- 地图切换后 Agent ID、Observation schema 和任务接口不变化。
- 不允许 Python 策略包含第二张地图目标的固定坐标。

### 通过标准

同一 checkpoint 能在两张地图运行，并在未见地图达到约定的最低泛化成功率。

## 16 每阶段交付记录模板

每个阶段完成后应记录：分支与 commit、修改文件、编译命令、UE 启动命令、地图、seed、演示操作、预期可见现象、实际截图或视频位置、自动化命令、Episode 数量、结果摘要、已知限制和下一阶段入口条件。

## 17 第一批建议实施范围

第一批只实施 S0 至 S3：先固化可视基线，再补蓝方受击状态、红方局部感知和发射车防空攻击。该范围完成后应形成第一个真正的主动对抗闭环，再决定是否立即加入狙击手和步枪兵协同。
